Why we divided the work this way

  • One lead per step. We followed the advice in the brief and gave each step one responsible person. Jayeeta led the data, Ammara the algorithm, and Nhan and Laura the website. All four of us shared the GitHub publication.
  • Handovers. The steps depended on each other, so we set handover dates. The XML file went to Ammara on 21 October, and the search went to Laura on 22 October.
  • One owner per page. Each page had its own owner, so that we could work at the same time without editing the same file.
  • Reviews and our own commits. Reviews on the main branch helped us avoid merge conflicts. Each of us committed our own work, so the history shows who did what.

How we worked

All four of us wrote the text on this people page.

  • Planning. We started from a brainstorm on academic articles with authors, publishers, topics and dates. Our first idea was to find which topics each publisher publishes most, ranked with a method such as bubble sort. We then chose to focus on filters first and to add a search bar if time allowed.
  • Tools. GitHub, Figma, Excel, VS Code, and Python with Flask.
  • Workflow. One shared GitHub repository, with branches and pull requests. Changes to the main branch are reviewed by at least one other member before they are merged.
  • Communication. Zoom meetings, a group chat, and a shared document for ideas, tasks and progress.
  • Personal information. We chose to show our full names and avatars, so no anonymised key is needed.
